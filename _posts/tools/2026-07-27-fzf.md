## 들어가며

터미널을 오래 쓰다 보면 명령어를 다시 찾거나, 파일 위치를 확인하거나, 파일 내용을 잠깐 열어보는 일이 자주 반복된다.

보안 진단 환경에서는 더 그렇다. 긴 명령어를 조금만 바꿔 다시 실행하거나, 여러 경로에 흩어진 스크립트와 워드리스트를 찾아야 한다. 기본 명령어만으로도 가능은 하다.

```powershell
Get-ChildItem -Recurse
Get-History
```

```bash
find . -type f
history | grep <검색어>
```

하지만 결과가 많아지면 다시 필터링해야 하고, 파일 내용을 보려면 별도 명령을 또 실행해야 한다. 이 과정을 줄이기 위해 `fzf`, `fd`, `bat`를 조합해서 다음 세 가지 명령을 만들었다.

```text
fh     명령 히스토리 검색
ff     현재 경로의 파일 검색 및 미리보기
ffh    숨김 파일을 포함한 검색 및 미리보기
```

## 사용한 도구

| 도구 | 역할 |
|---|---|
| `fzf` | 전달받은 목록을 대화형으로 검색하고 선택한다. |
| `fd` | 파일 목록을 빠르게 만들고 제외 경로를 제어한다. |
| `bat` | 선택한 텍스트 파일을 줄 번호와 구문 강조를 적용해 보여준다. |

흐름은 단순하다.

```text
fd로 파일 목록 생성 -> fzf로 검색 -> bat으로 내용 미리보기
```

## 완성된 사용감

설정을 마치면 Windows와 Kali에서 거의 같은 방식으로 쓴다.

```bash
fh
ff
ffh
```

경로를 지정할 수도 있다.

```powershell
ff C:\Pentest\02_Tools\Wordlists
```

```bash
ff /usr/share/wordlists
```

`ff`와 `ffh`는 전체 디스크를 무작정 뒤지지 않는다. 기본은 현재 디렉터리 기준이고, 인자를 주면 그 경로 기준으로 검색한다.

## 화면 구성

최종 형태는 이렇게 잡았다.

```text
왼쪽 목록: 기준 경로 아래의 짧은 상대경로
오른쪽 첫 줄: 실제 전체 경로
오른쪽 본문: bat preview
```

긴 경로를 그대로 왼쪽 목록에 보여주면 정작 파일명이 잘리기 쉽다. 그래서 목록은 `win-rebuild/windows/wsl-backup.ps1`처럼 상대경로만 표시한다. 대신 preview 첫 줄에는 실제 전체 경로를 표시한다.

## 큰 파일 preview 문제

처음에는 선택된 파일을 무조건 `bat`으로 열었다. 그런데 `.tar`, `.zip`, `.jar` 같은 큰 파일을 지나갈 때 preview가 멈칫했다. `bat`이 바이너리 여부를 판단하려고 파일을 읽기 때문이다.

그래서 preview helper에 skip 규칙을 넣었다.

- `.zip`, `.tar`, `.gz`, `.7z`, `.rar` 같은 압축 파일 skip
- `.exe`, `.dll`, `.jar`, `.msi` 같은 바이너리 skip
- 이미지, PDF, 암호화 파일 skip
- 10MiB 초과 파일 skip

이제 큰 파일을 지나가도 내용을 열지 않고 바로 메시지만 보여준다.

```text
[preview skipped] binary/archive file: .tar
size: 12753182720 bytes
```

## Windows 한글 파일명 문제

Windows PowerShell 5.1에서는 native command 파이프 인코딩 때문에 한글 파일명이 `????`로 깨질 수 있다. 이 상태에서 `fd | fzf`를 하면 목록도 깨지고, preview helper도 깨진 경로를 받아 파일을 찾지 못한다.

그래서 `ff` 함수 시작 시 UTF-8을 강제로 지정했다.

```powershell
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
$global:OutputEncoding = $utf8NoBom
try { [Console]::InputEncoding = $utf8NoBom } catch {}
try { [Console]::OutputEncoding = $utf8NoBom } catch {}
```

PowerShell 7에서는 보통 문제가 덜하지만, 같은 설정을 넣어두면 PowerShell 5.1과 7에서 동일하게 동작한다.

## CMD에서도 가능한가

파일 검색용 `ff`와 `ffh`는 CMD 버전으로도 만들 수 있다. `ff.cmd` 같은 배치 파일에서 `fd | fzf --preview ...` 형태로 구성하면 된다.

다만 `fh`는 CMD보다 PowerShell이나 zsh 쪽이 훨씬 낫다. CMD 히스토리는 세션 중심이고, 선택한 결과를 현재 입력줄에 자연스럽게 삽입하는 경험도 제한적이다.

| 기능 | CMD 가능 여부 | 비고 |
|---|---|---|
| `ff` 파일 검색 | 가능 | `.cmd` 스크립트로 구현 가능 |
| `ffh` hidden 포함 검색 | 가능 | fd 옵션만 바꾸면 됨 |
| `bat` preview | 가능 | 현재 Windows helper가 이미 CMD 기반 |
| 큰 파일 skip | 가능 | helper에서 처리 가능 |
| `fh` 히스토리 검색 | 제한적 | PowerShell/zsh 권장 |

## 마무리

이 설정의 목표는 복잡한 파일 관리 도구를 만드는 것이 아니다. 이전 명령을 빨리 다시 찾고, 필요한 파일을 검색하면서 내용을 바로 확인하는 동작을 줄이는 것이 핵심이다.

특히 보안 진단 환경에서는 워드리스트, 스크립트, 백업 파일, 설정 파일을 자주 오가기 때문에 `fh`, `ff`, `ffh`처럼 짧은 명령으로 통일해두면 손이 꽤 편해진다.
